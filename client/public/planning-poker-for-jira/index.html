Estimate Jira Backlog Items With Planning Poker

Planning poker is a consensus-based agile estimation technique: the team discusses a backlog item, everyone votes a card simultaneously, and the hidden reveal exposes disagreement before it turns into a bad estimate. It is the fastest way to turn a noisy sprint planning meeting into a clear set of Jira story points.

If you already track work in Jira, your backlog is your source of truth - the epics, stories, and bugs you need to size for the next sprint. This tool sits next to that backlog and handles the one thing Jira does not do well out of the box: anonymous, simultaneous, distraction-free voting that surfaces real disagreement instead of anchoring on whoever speaks first.

How to Run Planning Poker for Jira Issues, Step by Step

You need two browser tabs: your Jira board and a planning poker room. Jira stays the source of truth. The room only collects hidden votes and shows them at the same moment. Nothing connects the two, so you do not need a Jira admin, an API token or a plugin.

  1. Prepare the issues in Jira. Open the backlog or a filter with the stories you want to size, in priority order. Share this tab on your video call, so everybody reads the same description and acceptance criteria.
  2. Create a room. Open the free planning poker app, type your name and click Create room. The invite link goes to your clipboard (Invite teammates copies it again). Paste it in the call chat. Teammates open the link, type a name and join. Nobody makes an account.
  3. Choose who only watches. A Product Owner or a stakeholder who does not estimate clicks the microphone card to Observe (don't vote). The room lists observers, but they do not get a card on the table.
  4. Name the issue in the room. Type the key and title in the Item title field next to Reset, for example "SHOP-142 Add SSO to login", and press Enter. Everybody sees it on the table. Answer questions about scope before anybody votes.
  5. Vote at the same time. Each voter picks a card: 1, 2, 3, 5, 8, 13, 21, 34 or 55. More opens 89 to 610, ? means "I am not sure" and the coffee cup asks for a break. The table shows a check mark for each person who picked a number, never the number itself.
  1. Reveal. Each round, one random voter holds the star and is the only person who sees Reveal. The reveal shows every name with a card and a count such as "8 × 2, 5 × 1, 13 × 1". When all cards match, the room says Consensus. There is no average on purpose: the team agrees on a number, the app does not calculate one.
  2. Discuss and vote again. Ask the highest and the lowest voter to explain. Then click New vote and estimate the same issue again until the numbers meet. The field keeps the issue title for the new round.
  3. Record the estimate in Jira. Type the agreed number into the issue's Story point estimate field (team-managed projects) or Story Points field (company-managed projects). Do it before the next issue. The room sends nothing to Jira.
  4. Go to the next issue. Type the next key in the field, click New vote and repeat.

Before you close the call, open the Estimate log under the table. It lists every revealed round in order (#1, #2, ...) with its issue title, the vote counts and a consensus mark, without names. Compare it with the issues in Jira, so that no issue is left without points. A re-vote adds its own row with the same title. Rooms are kept in memory only: soon after everybody leaves, the room and its log are gone.

What's on the Roadmap: Jira and CSV Import

To be clear and honest: this tool does not yet have a built-in Jira integration. Today you type each issue key into the room and the points into Jira by hand - it is deliberately a no-plugin, no-OAuth setup so you can start in seconds without granting access to your Jira data.

Tighter integration is planned. On the public roadmap we have direct Jira import (pull a sprint or JQL query straight into a session) and CSV import (bulk-load a backlog exported from any tool). These are community-prioritized features. If a Jira or CSV import would make your sprint planning faster, vote for it on GitHub - the more votes a feature gets, the sooner it ships.

Frequently Asked Questions

Does this tool integrate directly with Jira?

Not yet. There is no built-in Jira integration today - you keep the issue open in Jira, vote in the room, and type the agreed story points into Jira manually. Direct Jira import is on the public roadmap; you can vote for it on GitHub.

Is it really free?

Yes. The tool is free and open source. There is no paywall, no per-user pricing, and no premium tier.

Do my teammates need to sign up or install anything?

No. There is no signup and no install. You share a room link and everyone joins in their browser - no Jira admin rights or marketplace approval required.

Can we estimate Jira story points with it?

Yes. Type the issue key into the room, vote, reach consensus, and type the number into the issue's Story Points field. The step-by-step guide above shows each click.

Does it work with Jira Cloud and Data Center?

Yes. The room never connects to your Jira instance, so the same workflow works with Jira Cloud, Jira Data Center, and any other issue tracker.
